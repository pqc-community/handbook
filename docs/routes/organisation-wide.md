This route is for a migration lead who is coordinating many assets across the organisation.

**Handbook practice:** Each role supplies one input to the plan.

| Role | Input |
| --- | --- |
| Executive sponsor | The decision to proceed |
| Migration lead | The one-page plan |
| Asset owners | The system and its unknowns |
| Procurement | The supplier questions |
| Legal or risk | The confidentiality period and the applicable timeline |
| Operations | The change window and the rollback owner |
| Suppliers | The product, version, and the answer |

Read in this order for the handbook's six steps:

1. Decide whether the handbook applies and name an owner.
2. Find cryptographic dependencies and record unknowns.
3. Assess confidentiality period, importance, and constraints.
4. Prioritise and choose a source-backed path.
5. Engage suppliers and migrate.
6. Verify what changed and set the subsequent review.

**Handbook practice**, citing ASD's [planning for post-quantum cryptography](https://www.cyber.gov.au/publication/planning-for-post-quantum-cryptography) publication: name an owner is the handbook's step before LATICE; find dependencies is Locate; assess the confidentiality period and constraints is Assess; prioritise is Triage; engage suppliers and migrate is Implement; verify the change, communicate it, and set the subsequent review is Communicate and educate. The handbook's six-step list and LATICE do not have the same number of steps.

A large bespoke estate, critical national infrastructure, or a regulated system needs a specialist as well as this route.

Then read these pages in order:

1. [Migration plan](/resources/migration-plan/)
2. [Diagnose](/migration-practices/diagnose/)
3. [Inventory](/migration-practices/inventory/)
4. [Priority](/migration-practices/priority/)
5. [Evidence record](/resources/evidence-record/)
6. [Subsequent review](/migration-practices/subsequent-review/)

The output is a one-page [migration plan](/resources/migration-plan/) with an owner for each asset and a subsequent-review date.
