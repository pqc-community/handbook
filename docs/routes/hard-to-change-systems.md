This route is for a product whose verifier, firmware, or release cycle cannot be changed quickly.

Can the verifier be updated later? When it cannot, read [long-lived roots](/algorithm-protocol-options/long-lived-roots/) before [signatures](/algorithm-protocol-options/signatures/).

Read in this order:

1. [Inventory](/migration-practices/inventory/)
2. [Release dates](/migration-practices/release-dates/)
3. [Long-lived roots](/algorithm-protocol-options/long-lived-roots/)
4. [Signatures](/algorithm-protocol-options/signatures/)
5. [Vendor plan](/migration-practices/vendor-plan/)
6. [Implementation](/migration-practices/implementation/)
7. [Change record](/resources/change-record/)
8. [Vendor response log](/resources/vendor-response-log/)

The output is one asset's vendor-release, test, production-deployment, and end-of-support dates, plus a [change record](/resources/change-record/).

**Primary next page:** [Inventory](/migration-practices/inventory/).

For a labelled illustration, not a real organisation, see [Protect this first](/resources/protect-this-first/).
